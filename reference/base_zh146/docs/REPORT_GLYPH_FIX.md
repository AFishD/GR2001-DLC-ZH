# REPORT_GLYPH_FIX —— 「右缘采样缺陷」乱码的根因与修复（GR_ZH130）

> 执行者：本轮 `fix/glyph-garble` 分支执行者 ｜ 日期 2026-10-19 ｜ 分支 `fix/glyph-garble`
> 用户报障：**部分文字/字形显示乱码**，点名举例 **大写 `X`（名字输入键盘）· `约` · `金`**。
> 结论：**三个都是同一个物理原因 —— 字形采样矩形的右缘正好压在贴图宽度 1024 上（引擎取不到那块像素）**。
> 该缺陷 **继承自基底**（K2 几何 2026-10-17 引入 64 列），不是本轮引入。
>
> 姊妹文档：`docs\STATUS.md`（状态与残余）· `tools\iso_build\patch_zh130_glyph_edge.py`（修复器，
> 文件头有完整根因/修法/自证清单）· `tools\final_fix\repro_from_eng_zh130.ps1`（从英文原盘端到端复现）。

### 1.6 机理与历史标定（为什么以前没被发现）

* 引擎 `ComputeCharTextureCoords` 把记录坐标当**半 texel**（`>>1`）归一化；**矩形右缘 == 贴图宽度
  （1024）时坐标落在归一化上界之外** ⇒ 采不到那块像素（`docs\han_v2\PS2_FONT_MECHANISM.md` §2.2）。
* 这条边界**被用户实拍标定过两次**：
  * round59（`docs\REPORT_edge_fix_zh109.md`）：「个」rect (1008,195,**1024**,211) = 斜纹方块；
    同批「这」(992,195,1008,211)（u1=1008）**正常** ⇒ 实测边界 = **只有 u1 == 1024 坏**；
  * K2 轮（`docs\CAPACITY_2400.md` §12.6）：`T`=(1016,192,**1024**,208) 等记录实拍"糊/缺横杠"，
    搬到 "货架 (u1 ≤ 1010)" 后 106 px 差异归零。
* **64 列几何是 K2 轮（2026-10-17）引入的**：`col = slot % 64` ⇒ col 63 的格 = x 1008..1023
  （右缘 1024）；而 round59 当年那条 ASCII 货架虽然搬过一次，**0x58 `X` 这一条落在了货架最右端**
  （x=1016..1024）—— 两处都踩线，且此前所有回归导航都只到"主菜单 + 记忆卡屏"，
  那些界面里**一个 col-63 的字都没有**（`心/该/给/引/候/总/约/金…` 全在正文与任务名里）
  ⇒ 1 帧粒度对照也照不出来。

## 2. 修法（只动"映射 + 那 36 个格 + 1 条记录"，**不动 ELF**）

修复器：`tools\iso_build\patch_zh130_glyph_edge.py`（只读输入、单次成盘、写盘前后各一遍硬断言）。

### 2.1 对偶路径：36 个 col-63 槽整体**换位**

* 目标槽 = 保留段（1872..2344）里 **PUA 占位 + 格内 0 墨 + `usable`（不被任何 FT 记录矩形压）+
  全盘 UI/.MIS 文本 0 引用** 的 36 个空槽（确定性取 slot 升序前 36 个 = **1978..2018**）。
* 换位 = 对偶槽**互换**（真字 ↔ 占位字符）：字形像素逐 texel 搬到新格、旧格清零；
  占位字符本来无字形（空模板）⇒ 被换到 col 63 后仍然是空的、且 **0 引用 ⇒ 永不采样**。
* 36 对 = **72 个码位变化**（`约 A7EC→B6B2`、`金 A8CE→B6B3`、`心 A4C6→B6AB`、`该 A5A8→B6AC`…）。
* 为什么不是"改 64 列 / 改引擎"：`NCOL 64→63` 会让**全部 2300 个槽**的格位整体变位
  （= 重铺整张图集 + 搬 182 条记录），风险远大于 36 格换位；换位只需重编码 72 个码位。

### 2.2 FT 路径：ASCII `0x58 'X'` 的记录矩形搬家

```
(1016,208,1024,224) u1=1024 ✗   ⇒   (360,627,368,643) u1=368 ✓   （三 face 同步改写）
```

像素逐 texel 搬过去、旧矩形清零；`pad`(=rec[0]) / `advance`(=rec[1]) **一个字节不动**；
落点在 ASCII 货架（`y=627..643`，行 37 = slot ≥ 2368 = 引擎不可寻址区）里紧接 `0x54 T` 之后的第一个空格。

### 2.3 文本层：盘上**全部**文本按码位重编码（复用项目现成机器）

`font_compact.plan_reencode()`（容器级登记表 `*_STRINGS.RES/_TXT/_SPECIAL_FEATURE.XML/IGORHELP.TXT`
+ 全盘粗扫/细扫 + ELF 文本区），实测只命中 **3 个容器**（其余 28 个登记容器与码位无关）：

| 容器 | 改动 |
|---|---|
| `MENU.IMG#25 EN_STRINGS.RES` | 192 字 / 384 B（重压 4 子流 → 32,860 B，槽 47,570） |
| `GR.IMG#902 EN_STRINGS.RES` | 192 字 / 384 B（重压 4 子流 → 32,861 B，槽 47,619） |
| `MENU.IMG#283 EN_SPECIAL_FEATURE.XML` | 207 字 / 414 B（重压 5 子流 → 41,462 B，槽 49,700） |

* 两个"命中 `texty()` 判据但不是文本"的压缩位图（`GR.IMG#171 M03_RRBRIDGE_SKY.BMZ` /
  `#2466 MAN_OLD02.BMZ`，解压流里的二进制巧合）用**新增的 opt-in 参数**
  `--exclude-container` 显式登记为二进制巧合（`font_compact.plan_reencode` 新增
  `res['exclude_text_containers']`，**不给该参数时行为与以前逐字节相同**）。
* `.MIS` / `.ATR` 家族**实测 0 段中文**（92 个 .MIS / 1460 个 .ATR 全部 `n_cjk=0`）⇒ 不需要动。

### 2.4 charset

`tools\font_pipeline\data\charset_compiled_zh16.json`：**文本级最小编辑**（只改那 72 条 `pair_of`
的 `[lead, trail]`）+ 追加 `_glyph_edge_zh130` 元信息节；`codes`/`mode`/`grid` 等字段逐字节不变。
