# RETROSPECT —— 试错记录（走过的弯路）

> 这份文件的价值不在"我们做成了什么"，而在**哪些判断是错的、错在哪、怎么发现的**。
> 只写有据可查的：每一条都能在 git 历史、`docs/archive/elf_specs/`、或保留的报告里找到证据。
> 面向未来的你：**动手前先读第 1、2 条**，它们各自烧掉了整整一轮。

## 1. 把「XML 元素值」当成「定长字段」——任务名连错两轮

**错误判断**：M15 的任务名 `White Razor` 是 11 字节，于是认定名字字段**定长 11 字节**，
换中文时必须补空格凑够 11 字节。

**实际情况**（`docs/REPORT_MISSION_NAME.md` §A.2）：

* 名字以 `<Name>` / `</Name>` 定界，**没有 NUL、没有长度前缀、不是定长**；
* 同盘 40 个任务的 `<Name>` 长度 **11..21 字节不等**（`T01 - Obstacle Course` 21、
  `DP05 Ravine` 11）—— 这一条就能直接证伪"定长"；
* 那 11 字节恰好落在一个 15 字节的 **LZO 字面量段**里（段内容 `- White Razor</`）。
  "只能动 11 字节"是**我采取的原地替换实现**的限制，不是格式的限制。

**代价**：v1/v2 用 `白刃` + 空格补到 11 字节 ⇒ 任务标题按名字宽度居中 ⇒ 标题被顶偏。
v3 才改成"让 sub0 的解压输出变短 7 字节，同步 `rlen` / `real` / `stored`"。

**教训**：在写死一个长度之前，先在同盘的**其它 39 个同类样本**上验证这个长度是否恒定。
如果它们不等长 ⇒ 长度是内容决定的，不是格式决定的。

**残留影响**：`GR_ZH145` 的 29 个名字仍用**空格补长度**的做法（未改成 v3 口径），
在居中标题上同样会偏 —— 这是 `docs/STATUS.md` 里登记的已知残余。

## 2. 把「引擎取不到像素」当成「位图坏了」——乱码查了一整轮

**错误判断**：用户报 `X` / `约` / `金` 乱码 ⇒ 先怀疑是画进图集的位图烂了。

**实际**（`docs/REPORT_GLYPH_FIX.md` §1.1）：把 2300 个对偶字的**引擎采样格**逐 texel
与 `方正像素16.ttf` 的 16px 渲染比对：

```
[focus] '约' pair=(167,236) slot=639 cell=(1008,147) ink=57 ttf_ink=57 xor=0
[focus] '金' pair=(168,206) slot=703 cell=(1008,163) ink=61 ttf_ink=61 xor=0
```

**xor = 0** —— 位图一个像素都没错。真正的物理原因：

* 图集宽 **1024**，网格 **64 列**，单元格 16 px ⇒ **col 63 的右缘正好 = 1024**；
* 引擎采样矩形 `u1 == 1024` 时取不到那一列；
* `X` 是 FT 记录里唯一一条 `u1 >= 1024` 的（large/default/huge 三面）；
* 全盘"踩这条线"的：**36 个 col-63 槽 + `X` 的 3 条 FT 记录**。

**教训**：报"乱码"时，**先证伪"数据错了"**（逐 texel 比对渲染源），再看**几何/采样**。
这一步做对了，后面 30 分钟就定位完；做错了就是一轮。

**修法**：把 col-63 的字**换到别的槽**（36 对偶换位）+ 改 `X` 的三条 FT 矩形，
写回 charset 时**只动 `pair_of` 的键、`codes` 一个不动**。

## 3. `0xFF` = EOF —— 把「词法器截断」误判成「内存/堆问题」

**症状**：13 条专家档案（SpecialistProfile）的正文只剩后半截，"显著特征" 显示成 "特征：无"。

**先期的错误方向**：怀疑内存/堆/字符串长度。实际是**一个字节**：

```
RSXMLLexan::GetCharData @0x00544450
  0x00544588  lb   $v1,0($a0)          ← 有符号字节加载
  0x0054458C  addiu $v0,$zero,-1
  0x00544590  bne  $v1,$v0,<正常字符>   ← 0xFF 被当成 -1 = EOF
```

而字符集把 `U+8457 著` 映射成**单字节 `0xFF`**。每个专家档案的第一处 `0xFF` 恰好落在
"显著特征"中间 ⇒ 节点被切断，`SFStudio::ParseItem` 又**覆盖**（不是追加）节点内容。

**教训**：

* 字符集里**任何**能产生 `0xFF` 的映射都是定时炸弹，哪怕语义上完全正确；
* 发现一个就**普查全盘**（`docs/REPORT_FF_SWEEP.md`：4713 个容器 / 26,483,238 个 0xFF
  逐一判类，A 类 = 0），并把判据固化成**构建闸门**；
* 修法优先改**内容**（`显著`→`明显`、`卓著`→`卓越`），不要为了一个字节改代码。

## 4. 卡死根因：从「文本溢出」查到「分配器桶链」

**阶段性误判**：任务完成处画面定死 ⇒ 先怀疑文本溢出 / 折行 / 堆耗尽，走了 `TEXT_OVERFLOW`、
`HEAP_EXHAUSTION`、`MEMDRIFT` 几条路。

**实际**（`docs/REPORT_DISASM_ROOTCAUSE.md`、`docs/REPORT_COMBFIX.md`）：
**分配器的桶链被写坏后，拿着坏指针在 RAM 内外读写** ⇒ 无限自旋 / 野读写。
四件套做的事都一样：把"链头非法"从**无限自旋**改成**走既有出口**。

| 名 | 站点 | cave | 一句话 |
|---|---|---|---|
| F4 | `0x00102588` | `0x0041A35C` | malloc 大块桶链扫描：链头不在 RAM 内就 bail |
| OOMFIX | `0x00539174` | `0x00550048` | 解压器 malloc 返回 NULL 时不再写 `NULL+4` |
| F7 | `0x001021D4` | `0x005DECC4` | own-bin 回边：链头非法就 bail 到"换下一个桶" |
| F7b | `0x00102208` | `0x00570BB0` | unsorted 桶快路径：链头越界就 bail |

**教训**："画面卡住"要二分的是**执行流**（是在转圈还是在等 I/O），不是文案。
ELF 层面只改 **239 字节 / 70 段**，全部落在声明窗口内，窗口外 0 字节 —— 这也是
"能用数据解决就不碰代码"的反面教材：这里**必须**碰代码，所以碰得越小越好。

## 5. 「折行 +8px 只会放标点」——假设被自己证伪

**假设**：特别收录正文再宽 8px，多出来的空间只会被标点占用，排版不会变。

**实测**（commit `5317f4cf`，`docs/REPORT_ZH143_WRAP8.md`）：**不成立** —— 多出的 8px
会被正文用掉，折行位置真的变了。于是这一轮的价值变成"把假设记下来，别再试第二次"，
而不是"验证通过"。

**教训**：涉及**排版**的假设，必须用真实文本跑一遍折行模拟（`tcslib.wrap_seg` /
`wrap_line_count`），不能靠"应该只会……"。

## 6. 「从上一版成品盘出发」被废止

早期为了省时间，链条从 `GR_REBUILD2400.iso` / 上一版成品盘起步。后果：
**中间盘一被清理，链条就断**，且无法回答"这张盘到底是怎么来的"。

**现行规矩**（写在 `fix_spec.json` 与 `BUILD_GUIDE.md` §1）：

```
base = f(英文原盘, K2 cdvd 转储)
```

不允许任何历史产物出现在基底链上。`GR_REBUILD2400.iso` 降级为"开发期快捷基底"，
而且它自己也能被 `rebuild_base.py` 4 秒重建出来（逐字节相同）。

## 7. 字库容量的三次改口径（1212 → 1504 → 2350 → 2300）

| 阶段 | 容量 | 做法 | 结果 |
|---|---|---|---|
| ZH16 | 1212 | 单字库 16px | 起步 |
| zh93 | 1504 | ELF 4 处 gate `sltiu …,0xAE` → `0xB1`，lead 扩到 `0xA1..0xB0` | 可行，但 gate 一改就动 Game CRC |
| r83 / 2400 | 2350 对偶 | 64 列图集 + 几何重建 | 容量够了，**但引入 col-63 右缘缺陷**（见第 2 条） |
| 现行 | **2300** | `lead 0xA1..0xBA` × `trail 0xA1..0xFE` | 稳定，1954 个已画字 + ~300 空槽 |

**教训**：扩容不是免费的 —— **64 列**这个决定直接把最后一列推到了贴图边界上，
代价是一轮乱码排查。容量、几何、采样三者必须一起验。

## 8. `tools/` 长到 1681 个文件

每一轮都往 `tools/` 扔一次性脚本（`tools/rounds/**` 999 个），到收尾时已经没人能说清
哪个还在用。本轮的处理：

* **只留**构筑链上的（18 个阶段 + 共用库 + 文本工具）；
* 一次性脚本按"删 + 登记"处理，清单在 `docs/archive/REMOVED_DOCS.md` 与
  `docs/REPORT_FINAL_DELIVERY.md` §B；
* 判断依据不是"看起来有用"，而是**`build.py` 的调用链 + 保留文档的引用**。

**教训**：一次性脚本诞生时就该带"过期即删"的标记；否则收尾成本会超过写它的成本。
