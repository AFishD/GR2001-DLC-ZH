## B. 本轮做法（可变长度）

每个条目（80 份，逐一规划）：

1. **解 sub0**（`lz77_decode.py` 口径），取 `<Name>`；DP01–DP05 的 `<MapName>` 与 `<Name>`
   同值 ⇒ **两处一起改**（否则旧名残留在 `<MapName>` 里）。
2. 把名字段换成语言表译名（`work\builds\GR_MISNAMES\out\map.tsv`，40/40 官方译名），
   **不加任何空格**；解压流因此**变短** |Δ| = 2..9 B（DP 组两处 ⇒ 4..12 B）。
3. **窗口重编码**：名字覆盖的项目 + 相邻边界，用 DAG 最短路 DP 以**最小字节数**重新编码
   （状态机 = 长字面量段 / M2 / M3 / M4 / M4L / M1，与 `lz77_decode.py` 一致）。
4. **匹配修复**：
   * 「源在改动区之前、目标在改动区之后」的匹配，`back` 整体平移 Δ（back 变小，不会超容量）；
   * 其余逐个校验 `target[mo-back…] == target[mo…]`，不成立就找**最近的等值源**重指；
   * 找不到等值源 ⇒ 在附近用同一个 DP **局部重编码**（左/右边界各试 0..12 项）。
5. **载荷长度精确补回原值**（关键）：
   * 太短 ⇒ 在窗口之后**最近处**找「匹配 → 等值长字面量」(+1..+31，精确凑数) 或 `M2→M3` (+1)；
   * 太长 ⇒ 尾字面量裁剪（解码器读不到的那部分）或锚点附近窗口重编码**找省**（-1..-4/窗口）。
6. 于是 **`clen`（sub0 载荷长度）不变 ⇒ sub1..N 文件偏移不变 ⇒ 条目 `stored` 不变**；
   只有 sub0 的 `rlen` 和条目 `real` 各减 |Δ|。

**与 v3 的差别**：v3 把补偿 op 放在离名字 400 多字节处（且只适用于名字在单个字面量段）；
本轮把补偿放在**名字窗口紧后面**（或最近的等值机会），把「整体位移窗口」压到最小 ——
同一套原理，全盘差异从「整条子流后半段」降到 **69.7 KB / 80 条目**（平均 870 B/条目）。

**每 5 个任务落盘一次自检**（任务书要求）：实际执行 8 次
（D01..D05 / ..DP02 / ..M02 / ..M07 / ..M12 / ..T02 / ..T07 / ..TAC05），
每次写完立刻从盘上回读全部已写条目，**8 次均 0 错误**（日志 `out\_run_all2.txt`）。

### B.3 长度调节是怎么做到的（每类给例子）

| 机制 | 用在哪 | 量 | 条数 | 例 |
|---|---|---|---|---|
| 反优化（匹配→等值长字面量） | 大多数条目 | +1..+8 | **58** | M15 `out=0x1AE` 2 B 匹配 → 8 B 字面量 (+6) |
| `M2→M3`（同 back 同长度） | 反优化凑不准时的 ±1 微调 | +1 | **0**（本轮没用上：反优化的 +1..+8 已能精确凑数） | — |
| 窗口找省（DP 重编码更便宜） | T02/T03/T06/T07/TAC01–05 | -1..-4/窗口 | **76** | TAC03 items[61..70] 32→30 (-2) |
| 尾字面量裁剪 | 本轮未用（末项目都是匹配） | 0 | 0 | — |

> 合计 **134** 个长度调节 op（反优化 58 + 找省 76）；所有 op 都只动**令牌**、不改解压输出；
> 每个条目最后一次 `lzo1x_decompress` 逐字节比对兜底。
