## B. 逐任务改动与自检

### B.1 技术（与上一轮 M15 同一套，只是通用化）

1. 条目 = 若干 `{u32 clen}{u32 rlen}{payload}` 子流（本批 1–7 条）；名字在 **sub0**，
   由 `</Name>` 定界，**无 NUL / 无长度前缀**，`rlen` 固定 ⇒ **替换必须恰好等长**，短了补 `0x20`。
2. **陷阱（M15 轮已证）**：名字字节会被**后续 LZO 匹配当源**引用，只改名字会把其它文本写成乱码。
   本轮把"依赖修正"做成通用能力：
   * 标出"**源区间压在改动区**"的匹配（以及输出压在改动区的匹配）；
   * 把相邻问题区合成**窗口**，用 **DP 做窗口内的最优解析**（按本工程 `lz77_decode` 的 LZO1X 语法：
     状态 0/1/2 = 自由 / 长字面量段之后 / 匹配后置字面量之后；候选 M2/M3/M4/M4L + 后置字面量），
     输出逐字节等于"只有名字变化"的期望；
   * **整条子流统一记账**：窗口可以比原编码短（省下的字节记入 credit，后面的窗口可以用）；
     重建后若比原载荷短，把若干 **M2 升成 M3**（同 back 同长度，令牌 +1 B）补齐；
     若比原载荷长，允许**最多 +24 B**，占用该条目与其后一条目之间的**空隙**
     （IMG 表 `stored` 字段同步 +N，`real` 不变）。
3. 每个条目都**回读自证**：整条条目（全部子流）解压结果必须逐字节等于期望值。

### B.3 被跳过的 11 个（如实单列）

`D02 火柱`、`DP02 农场`、`M01 铁龙`、`M02 急烟`、`M06 妖火`、`T02 轻武器`、`T03 榴弹`、
`T07 指挥`、`TAC03 爆破`、`TAC04 反载具`、`TAC05 防御`

**原因统一：LZO 结构无法在"等长"约束下安全重编码。** 具体两类：

1. **名字整段是匹配复制**（DP02 典型）：`<Name>` 的字节全部由 `back` 指向 `<MapName>` 的匹配产出，
   原编码只花 ~2 B 就产出 13 B；换成中文必须新写 4–8 B 字面量，而窗口内没有等量可省。
2. **名字被"独有文本"引用**（M01/M02/M06/T02/T03/T07/TAC03–05 典型）：名字里 `ing `、` R`、`te `、`the `
   之类被后面的简报正文/XML 当字典抄走，而这些匹配所在位置附近**没有第二个源**、也没有可省的冗余
   （该段正文本身是"独有文本"，重编码只会更贵）。窗口放大到 500 B、允许借用后面窗口的信用、
   允许最多 +24 B 空隙后仍然装不下 ⇒ 按"不冒险"原则跳过。

> 这 11 个的**译名已经查清并落在 `map.tsv` 里**，只差落盘。

## E. 未达成 / 风险

1. **11 个任务没做完**（见 B.3），原因集中在"名字被独有文本当字典引用 / 名字整段是匹配复制"，
   在**严格等长**（`rlen` 不变）约束下装不下。要全部做完必须允许**改变子流输出长度**
   （删掉名字尾部的填充空格，`rlen`/`real`/`stored` 一起改）——
   这正是并发那一路正在给 M15 做的方向，本轮没有跟进（会与对方冲突）。
2. **基底链不是任务书写的 144**：144 在本轮被并发改写（sha 不符、v3 脚本报错），
   145 改从 143 一次生成（含 M15）。若最终发布要以"新的 144"为基线，需要用同一脚本重跑一次。
3. **未跑模拟器**：只做了"解压层逐字节等价"的证明，没有实机画面证据。
4. **填充空格的排版副作用**：`M09 - 蓝色风暴` 只补 2 个空格，而 `D02 - 火柱` 要补 9 个；
   若标题是**居中**绘制，补得多的会略微左移（上一轮 M15 报告已提示过同一风险）。
5. **168 B 的"条目外"差异**是 IMG 表 `stored` 字段 + 条目后空隙里的增长尾部，已逐字节核对，
   没有越界到别的条目（构建脚本对每个增长断言 `0 ≤ grow ≤ gap`）。
6. `.MIS` 的 `<Name>` 是否就是玩家看到的那一份，仍未实机确认（上一轮 M15 报告也留了这条）。
