## A. 从 JSON 建「权威术语表」

### A.1 JSON 结构摘要（实测，非猜测）

- **不是**结构化的"术语库/翻译表"，而是**一段 Gemini（`models/gemini-3.8-flash`，`thinkingBudget=-1`）对话日志**：
  `{"runSettings": {…}, "systemInstruction": {}, "chunkedPrompt": {"chunks": [171 条], "pendingInputs":[1]}}`
- 每条 chunk = `{text, role, tokenCount, createTime}`；**role 分布 user 57 / model 114**，正文字符合计 **579,024**。
- 每个问答的固定节奏：`user` 发英文原文（或中文指令）→ `model` 一条 thinking（长，2k–18k 字符）→ `model` 一条**成品**（短，500–7,700 字符）。
- 成品有两种形态：
  - **Q0–Q6**：`### 方案 A / 方案 B` + 每行 `> **……**（N字）`（行数版式，含字数批注）；
  - **Q9 起**（用户在 Q9 明令「以后每一行的换行都使用 {Warp} 来替代」）：`#### 【直接复制文本】` + 一行反引号包住的 `{Warp}` 串。
- 问答覆盖（57 条，与 SFXML 正文 58 条中 57 条一一对应）：

| 段 | Q 区间 | 条数 | 对应盘上条目 |
|---|---|---|---|
| 武器/装备说明 | Q0–Q87（步长 3） | 30 | `SFXML:T0011–T0040` |
| 勋章/勋表 | Q90–Q108 | 7 | `SFXML:T0043–T0049` |
| 战役背景（何为幽灵/兵种/东欧/非洲） | Q111–Q120 | 4 | `SFXML:T0063–T0066` |
| 开发手记一/二/三 | Q123–Q129 | 3 | `SFXML:T0067–T0069` |
| 13 名专家档案 | Q132–Q168 | 13 | `SFXML:T0050–T0062` |

- **JSON 未覆盖**：`SFXML:T0010`（M18 Claymore 定向反步兵地雷）、全部 145 条 `<item/group/studio name=…>` 标题、`EN_STRINGS.RES` 的 2,192 条、`EN_STRINGS.TXT` 的 222 条 —— 这些正是本方案的主战场。

## C. 统一方案（可执行规格）

### C.1 落地前提（139 或 140 都成立）

1. **140 已产出并已实测**：`GR_ZH140.iso` = 139 + 9 个字形 + 44 条 SFXML 正文按 JSON 重写；**145 条 `name=` 属性 0 变化、LANG 2,192 条逐字节相同**。⇒ 本方案的 56 条标题 + 26 条 LANG 改动与 140 **完全正交**，先后顺序不限，**落在 140 上是首选**（这样标题与正文都已经是 JSON 口径）。
2. **一切按 `entry_index`（`A####`/`T####`）定位，绝不用 `offset`**：140 已使正文长度变化 −111 B，SFXML 里所有属性 `offset` 都已漂移；注入器按序号定位并逐字节核对，`offset` 只作自检。本报告 CSV 里的 `offset` 是 **139 快照**，不要照抄。
3. **每次注入都必须用当次盘新 dump 的表**（`dump_text_csv.py` + `dump_sf_titles_csv.py --allow-roundtrip-diff`）。
4. **LANG 两个拷贝必须同写**（MENU.IMG#25 + GR.IMG#902），SFXML 只写 MENU.IMG#283（西文/英文 5 份副本一个字节都不许动）。
5. 标点：140 已把 `×`/`…` 定为 ASCII 等价写法（`x` / `......`），本方案**沿用该口径**；只有用户要求"与 JSON 逐字一致"时才走 A.3 的补画路线（slot 2033/2034）。
